GROUP 4 – Airline Reservation and Flight Management System 1. Case study background An airline operates domestic and international flights connecting multiple airports. It manages passengers, flight schedules, aircraft, seat availability, ticket reservations, payments and crew assignments. The airline faces challenges such as double seat bookings, delays in retrieving flight information, inconsistent booking records and difficulties coordinating flight information across airports. The airline plans to implement an Integrated Airline Reservation and Flight Management System (IARFMS). 2. Problem statement Design a database system that manages flight schedules, passenger details, aircraft assignments, ticket reservations, payments and airport operations while supporting simultaneous booking requests and distributed information sharing. 3. Implementation tasks Experiment 1 – Relational database using SQL Create the following tables: • Passengers(Passenger_ID, Name, Email, Contact) • Airports(Airport_ID, Airport_Name, City) • Aircraft(Aircraft_ID, Aircraft_Model, Capacity) • Flights(Flight_ID, Source_Airport, Destination_Airport, Aircraft_ID, Departure_Time) • Reservations(Reservation_ID, Passenger_ID, Flight_ID, Seat_Number, Booking_Status) • Payments(Payment_ID, Reservation_ID, Amount, Payment_Status) • Crew(Crew_ID, Name, Designation) Perform JOIN queries to retrieve passenger flight details, identify available seats, manage permissions and demonstrate transaction control. Experiment 2 – Advanced MySQL programming • Create a VIEW for passenger flight reservations. • Create a TRIGGER to prevent duplicate seat assignments. • Develop a procedure to book flight tickets. • Create a function to calculate ticket charges. • Use a cursor to generate flight-wise passenger lists. Experiment 3 – Performance optimisation • Analyse flight search and reservation queries using EXPLAIN. • Implement B-Tree indexes on Flight_ID and Passenger_ID. • Create a computed hash column for ticket reference lookup. • Compare query performance before and after indexing. Experiment 4 – Transaction management • Demonstrate ACID properties during ticket reservation. • Simulate multiple passengers attempting to book the same seat. • Implement shared and exclusive locks. • Demonstrate deadlock during concurrent seat reservation and payment operations. • Examine MVCC during concurrent flight searches and booking updates. Experiment 5 – Redis and MongoDB • Redis: Store passenger sessions, frequently searched flight information and temporary seat-hold information with expiry. • MongoDB: Store passenger travel preferences, baggage details, travel history and flexible booking documents. • Perform CRUD operations and aggregation for flight-wise passenger statistics. Experiment 6 – Cassandra and Neo4j • Cassandra: Store flight activity and passenger travel event records using Flight_ID as a partition key. • Neo4j: Create Passenger, Flight, Airport and Aircraft nodes. • Establish BOOKED, DEPARTS_FROM, ARRIVES_AT and OPERATED_BY relationships. • Identify possible connecting flights between two cities. Experiment 7 – Distributed databases • Simulate three airport operational nodes. • Partition reservation records based on Flight_ID or airport region. • Replicate flight schedules across airport nodes. • Implement sharding of passenger reservation records. • Demonstrate eventual consistency when flight status changes at different nodes. 4. Expected outcome An integrated airline database supporting flight scheduling, passenger reservations, seat allocation, ticket payments and airport-level information management.
